# OPC UA SCADA Demo — симулятор ПЛК, историан и дашборд на Python

Учебный проект уровня «мини-SCADA»: OPC UA сервер, имитирующий ПЛК с технологическим узлом
(ёмкость + насос + нагреватель), клиент-коллектор, который по подписке пишет данные в SQLite
и ведёт журнал алармов, и веб-дашборд на Streamlit с трендами и управлением уставками.

```
┌──────────────────┐   OPC UA (Subscription)   ┌─────────────┐   SQLite (WAL)   ┌────────────┐
│  simulator/      │ ───────────────────────▶  │ collector/  │ ───────────────▶ │ dashboard/ │
│  plc_server.py   │ ◀───────────────────────  │ collector.py│                  │ app.py     │
│  (asyncua Server)│   write (уставки)         │ (asyncua    │                  │ (Streamlit)│
│                  │ ◀─────────────────────────┼─Client)─────┼──────────────────│            │
└──────────────────┘                           └─────────────┘                  └────────────┘
```

## Что внутри

| Компонент | Файл | Что делает |
|---|---|---|
| Симулятор ПЛК | `simulator/plc_server.py` | OPC UA сервер. Адресное пространство `PLC1/{Tank,Pump,Heater,Pipe,PLC}/*`. Внутри — «программа ПЛК»: ПИ-регулятор уровня с anti-windup, блокировка насоса от сухого хода с гистерезисом, термостат, heartbeat, периодические возмущения (падение/всплеск притока, забитый выход) |
| Коллектор | `collector/collector.py` | OPC UA клиент. Один Subscription, MonitoredItem на каждый тег, `queuesize=10`. Данные складываются в очередь и пишутся в БД пачками раз в секунду. Контроль связи по heartbeat, переподключение с экспоненциальным backoff |
| Хранилище | `collector/storage.py` | SQLite в режиме WAL: `measurements` (историан), `alarms` (журнал с ts_on/ts_off), `events` (связь, ошибки) |
| Движок алармов | `common/alarms.py` | Уставки LL/L/H/HH (ISA-18.2), мёртвая зона на снятие, эскалация H→HH и обратно. Чистая логика, покрыта тестами |
| Конфигурация тегов | `common/config.py` | Единый список тегов: NodeId, описание, единицы, тип, writable, уставки. Используется и сервером, и клиентом, и дашбордом |
| Дашборд | `dashboard/app.py` | Текущие значения с подсветкой алармов, тренды за N минут, активные алармы, журналы, панель управления (запись уставки/команд в ПЛК через OPC UA) |

## Запуск

Требуется Python 3.11+.

```bash
python -m venv .venv
.venv\Scripts\activate        # Windows
# source .venv/bin/activate   # Linux/macOS
pip install -r requirements.txt
```

Три терминала:

```bash
python -m simulator.plc_server          # 1. ПЛК: opc.tcp://127.0.0.1:4840/plc-sim/
python -m collector.collector           # 2. сбор данных -> data/scada.db
streamlit run dashboard/app.py          # 3. http://localhost:8501
```

Тесты:

```bash
pytest
```

Настройки через переменные окружения: `OPC_URL`, `DB_PATH`, `SUBSCRIPTION_PERIOD_MS`, `PLC_CYCLE_S`.

## Что посмотреть в демо

1. Открой дашборд — уровень выходит на уставку 55 %, температура греется до 60–66 °C (термостат).
2. В сайдбаре измени уставку уровня на 90 % — через 10–20 с сработает аларм `Tank.Level H`, затем `HH`.
3. Нажми «Насос: СТОП» — уровень поползёт вверх, давление упадёт (`Pipe.Pressure L`).
4. Останови симулятор (Ctrl+C) — коллектор начнёт переподключаться, активные алармы закроются с пометкой `[connection lost]`, в «Системных событиях» появится `disconnect`. Запусти снова — подпишется сам.
5. Подключись любым OPC UA клиентом (UaExpert, Prosys OPC UA Browser) к `opc.tcp://127.0.0.1:4840/plc-sim/` без шифрования — увидишь то же адресное пространство.

## Вопросы с собеседования, на которые отвечает этот проект

- **Чем OPC UA отличается от OPC DA / Modbus?** Платформонезависимый (не COM/DCOM), встроенная модель безопасности, информационная модель (объекты, типы, ссылки), а не плоский список регистров.
- **Polling vs Subscription?** В проекте используется Subscription: сервер сам присылает изменения с заданным publish interval, клиент не долбит сервер запросами `Read`. Это экономит трафик и даёт SourceTimestamp от источника.
- **Что такое MonitoredItem, publish interval, sampling interval, queue size?** См. `create_subscription(500, handler)` и `subscribe_data_change(nodes, queuesize=10)` в коллекторе.
- **Зачем heartbeat?** Отличить «значения не меняются» от «связь умерла». Коллектор поднимает ошибку, если данных нет 5 с.
- **Как устроены уставки алармов и зачем гистерезис?** `common/alarms.py`: без мёртвой зоны аларм на границе будет «дребезжать» включаясь/выключаясь каждый цикл.
- **Что такое anti-windup и зачем он в ПИ-регуляторе?** `PlcProgram.level_pi`: ограничение интегральной составляющей, чтобы после насыщения клапана не было большого перерегулирования.
- **Защита от сухого хода с гистерезисом** — `PlcProgram.pump_interlock`: стоп при <12 %, пуск только >18 %.
- **Почему запись в БД пачками?** Одна транзакция на N строк в разы быстрее N автокоммитов; SQLite WAL позволяет читать дашбордом параллельно с записью.
- **Как переживается обрыв связи?** Переподключение с экспоненциальным backoff (1→2→4→…→30 с), очистка состояния алармов, запись события.

## Куда развивать

- Заменить SQLite на TimescaleDB/PostgreSQL или InfluxDB — настоящий историан.
- Добавить в сервер OPC UA Alarms & Conditions (события вместо «алармов на клиенте»).
- Включить SecurityPolicy Basic256Sha256 + сертификаты + пользователей.
- Второй протокол: Modbus TCP (`pymodbus`) к тому же симулятору — отработать мост Modbus→OPC UA.
- Экспорт в MQTT (Sparkplug B) — IIoT-сценарий.
- Запаковать в Docker Compose.
